## 3. Loss-counter semantics

The [counter audit](M10.5-COUNTERS.md) cites both web drafts and the actual
Chromium153 source revision `971a7443b0c9b0a9b2860529b33331b76077ec62`.

| Counter or timestamp | What it establishes |
|---|---|
| rVFC `presentedFrames` | Cumulative current frames submitted for composition, not callback deliveries or physical scanout |
| Callback gap / runtime skip | Missing increments between delivered latest-frame metadata; first source callback after start has synthetic delta1 |
| `mediaTime` | Observed frame PTS; repeats across loops/seeks, not a unique lifetime ID |
| `presentationTime` / `expectedDisplayTime` | UA composition submission / predicted visibility, not application GPU completion |
| `totalVideoFrames` | Quality denominator; Chromium exposes decoded/admitted total, potentially including queued frames |
| `droppedVideoFrames` | Reported playback-quality drops, including renderer/compositor accounting; not decoder-only |
| Application attempt | Entry to actual pipeline tick before import/encode/submit |
| Application rendered/submitted | Successful synchronous submit path reaching the existing session callback, not GPU completion or visible canvas presentation |

An installed compositor frame can increment `presentedFrames`, later be unconsumed
and counted dropped, while JS misses its callback. Coalesced callbacks receive
latest metadata rather than replaying intermediate frames. Conversely, a callback
gap can occur while native video was consumed normally. Native12s probe: control
702 callbacks/719 presented/17 gaps/0 quality drops; bounded50/100/200ms stalls
620/719/99/0. These observations establish non-equivalence, not M10's intersection.

JS exposes neither dropped-frame IDs nor atomic cross-API snapshots; publication
can lag. Generation, PTS and submission sequences identify observations, not the
exact imported native frame. Exact unique loss and overlap remain **not measured**.

## 4. Metric decision

Keep the historical combined metric binding:
`100 * (runtime skips + quality dropped delta) / runtime presented delta`.
Overlap cannot be quantified, so no lower replacement metric is introduced.
This remains a registered score, not an exact count of unique physical losses.

Report quality-drop percentage against quality total, native callback-gap
percentage against native presented delta, attempt-minus-submission deficit,
rendered-vs-presented deficit and combined loss separately. Do not add percentages
with different denominators or subtract an assumed intersection. Missing/reset
operands stay unavailable; no unknown count becomes zero. Two independent
primary-source reviews approved this conservative decision before final runs.

## 7. Causality

**Supported:** callback deficits exist without extension installation or GPU
processing, and all observed runtime attempts in the controlled/final captures
reached successful submission. **Unknown:** precise browser/media scheduling
mechanism, unique physical playback loss and any isolated adapter contribution.
Neural shader cost alone does not explain the observations. No thermal, GC or
GPU-saturation attribution is supported.

Separate12s media/blink Chrome traces: bare718 current-frame updates/672 callback
batches; matched harness716/668; extension718/682. Drop batches reported47 and38
in the two active traces; none recorded in the bare trace. No trace data loss;

do not expose a shared dropped/missed frame ID. Callback-batch synchronous p95
was0.095/0.375/0.477ms, not GPU duration or full task occupancy.
[Trace evidence](../results/m105-trace.json).
