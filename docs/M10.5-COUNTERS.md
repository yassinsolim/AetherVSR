# M10.5 delivery-counter audit

## Definitions and implementation

Audited browser revision: `971a7443b0c9b0a9b2860529b33331b76077ec62`,
Chrome 153.0.8010.12. Definitions come from the
[rVFC draft](https://wicg.github.io/video-rvfc/) and
[Playback Quality editor's draft](https://w3c.github.io/media-playback-quality/),
not field-name inference. These drafts are not finalized W3C Recommendations.

| Observation | Meaning and limitations |
|---|---|
| rVFC `presentedFrames` | Cumulative frames submitted for composition, not callback deliveries or acknowledged physical display |
| rVFC callback delivery | One registered callback invoked with latest available metadata; missed intermediate callbacks are not replayed |
| Callback gap / AetherVSR skip | `max(presentedDelta-1,0)` between delivered callbacks; the source forces its first delta after start to 1 |
| `mediaTime` | Latest metadata frame's media PTS, seconds; repeats on loop/seek, not a lifetime native ID |
| `presentationTime` | UA composition-submission time, not AetherVSR queue submission |
| `expectedDisplayTime` | Predicted visibility time, not observed scanout |
| `totalVideoFrames` | Draft: displayed+dropped; Chromium player exposes decoded/admitted cumulative count, potentially including queued/preroll frames |
| `droppedVideoFrames` | Reported predecode/deadline/renderer drops, NOT decoder-only; no dropped-frame identity or individual drop timestamp |
| AetherVSR attempt | Diagnostic entry to the actual `VideoPipeline.onTick`, before import/encode/submit |
| AetherVSR submitted/rendered | Post-submit callback/session counter, not asynchronous GPU validation, GPU completion or actual canvas display |

## Answers to the accounting questions

1. **One frame can enter both populations in this implementation.** An installed
   current frame increments `presentedFrames`; if unconsumed, later rendering can
   count it dropped. A stalled JS observer can miss that same intermediate frame.
2. **A callback gap can include a quality drop**, but can also include a normally
   consumed native-video frame. A simultaneous rise proves neither exact overlap
   nor a shared cause.
3. `presentedFrames` means submitted for composition, not confirmed display or
   callback count. Even a later context-loss replacement can affect the counter.
4. Native frame installation increments the presentation counter. Coalescing
   delivers latest metadata once; JS callback sequence increments only when that
   observer actually runs. Different registered callbacks can share metadata.
5. The M10 components are not a common disjoint numerator/denominator population.
   Quality totals can publish asynchronously and include queued frames; the
   denominator is runtime rVFC-derived presented count, not quality total. M10
   pipeline FPS divides counter deltas by its wall window, with active duration
   checked separately. Native observer boundaries differ slightly and are retained.

Quality counters reset on resource load, not necessarily on ordinary seeking or
looping. The observer retains load generation and records loop/seek events. A
rewound PTS is not a counter reset. Missing/reset/invalid counters stay unavailable,
never coerced to zero. Submissions retain observation sequence, source generation
and metadata timestamps, but those fields do not identify the actual imported
native frame if the compositor advances between callback and import.

Recipe: `caffeinate -di node tools/m105-accounting.mjs .cache/m105/counter-probe-01`.
Two 12-second windows after 5-second warmup, control then deliberate 50/100/200-ms
main-thread tasks at 3/6/9 seconds. Both passed playback/focus boundaries.

| Control | 702 | 719 | 17 | 0 |

Long-task observations in the stimulus arm were 50, 100 and 200 ms. This shows
missed callbacks without reported quality drops; it does NOT measure overlap in
M10 or prove physical display continuity. This single ordered pair is not a
variance estimate or neural causality experiment. Initial Screen values were
viewport-emulated (1200x820, DPR1), so this evidence cannot establish physical
display placement/refresh. The corrected comparison apparatus uses native bounds
and clears device-metrics overrides; the preliminary raw files are not rewritten.

## Metric decision before acceptance registration

Exact unique loss/overlap is **not measured and not recoverable from these JS
cumulative counters alone**. Therefore retain M10's registered combined metric
as binding, not as an exact unique-loss estimate. M10 remains PARTIAL. No lower
replacement canonical metric is selected. Report alongside it:

- Quality-drop rate: quality dropped delta / quality total delta.
- Callback-gap rate: summed missing metadata-counter increments / native presented delta.
- Submission deficit: actual pipeline attempts minus successful post-submit callbacks.
- Rendered-vs-presented deficit: (runtime presented - submitted) / runtime presented.
- Historical combined: (runtime skips + quality dropped delta) / runtime presented.

Ratios above are percentages in reports. No subtraction/deduplication without
frame-identity evidence. Expose boundary residuals and source discontinuities;
PTS interval summaries exclude and count backward/generation spans explicitly.
No neural/controller/precision/graph change is justified by this audit.

## Review and instrumentation limits

Independent source audit identified the concrete overlap path. Independent code
review required null-safe ratios, explicit PTS exclusions, bounded/drained task
observation, stimulus/overflow checks and native display sizing. Those apparatus
corrections are regression-tested before controlled runs. Post-submit sequence
is explicitly not a native frame ID. Exact application attempts were added after
the preliminary probe; inactive arms correctly have no submission rate.

Long tasks select entries starting inside the measurement window, retain full
duration, and drain pending observer entries after completion; boundary duration
may extend past the window. Instrumentation adds work: metadata appends occur
outside M10's old bookkeeping bracket, rAF/observer wrappers are additional, and
neither represents total renderer CPU. Aligned and reduced-instrumentation
comparators are required before attributing small differences to the adapter.
No GC/thermal/internal-browser cause is inferred from these counters.
