# M10.5 controlled attribution protocol

Counter audit precedes this protocol; final acceptance is a later, separate
preregistration. No production runtime/geometry behavior changes before the
initial long replications. No M10 result is retroactively replaced.

## Environment and apparatus

Exact M9 worktree `2c62a2cf27decc6c88c8636ee85be1e76544a63b`, exact M10
worktree `acb50f8e69aa2893e221d654edb7d22e7876636e`; clean, each with npm ci.
Root comparison Vite/esbuild toolchain is the shared serving apparatus, not a
claim that each historical Vite was executed. HTTP raw modules/model/media and
matched HTML are hash-verified. M10 production extension payload is unchanged.

Chrome153.0.8010.12, same Apple M5/24GB/macOS26.6.2, AC power. Native AppKit
inventory: built-in Retina1512x982 logical pixels, scale2, origin(0,0); VG248
1920x1080 scale1 at(1512,-98). Place window entirely on built-in display:
(40,40),1200x903 outer, **1200x760 actual content**. Native 820px content does
not fit with current Chrome toolbar; macOS clamps it. Screen/DPR/bounds are
asserted at boundaries; rAF cadence is observable scheduling, not physical
refresh measurement. Physical refresh, temperature, energy and GC are unmeasured.

Legacy-M10 replication alone preserves its emulated1200x820/DPR1 viewport and
original fixture. Native window remains pinned to the built-in display, separately
verified before emulation and after capture. These replicas are not pooled with
native-DPR2 matched runs. Initial counter-probe-01 also used emulated dimensions,
and smoke-01 failed native sizing before measurement; retain both limitations.

All native capture arms use the same observer/recorder implementation. No focus
emulation/repair while recording. Native action and foreground setup happen before
five-second stable-readiness warmup. Any blur, hidden state, source/rate/error or
pause/play change invalidates the entire window; no splicing. Invalid captures
keep raw/hash/reason and are repeated with new names, not silently overwritten.
The cases file is fixed/hash-pinned; stopped schedules identify remaining unrun
cases. `CAPTURED` means integrity, not performance acceptance.

## Fixed comparison arms and ordering

Each window30s, after5s warmup. Four blocks, separate fresh browser per arm:

1. M9-harness, M10-harness, bare, idle, no-runtime, matched-harness, neural, baseline.
2. Reverse block1.
3. bare, idle, no-runtime, M9-harness, M10-harness, matched-harness, neural, baseline.
4. Reverse block3.

This is position/order-balanced, not fully carryover-balanced. Runs, not frames,
are independent units. Report every valid trial, range and paired differences;
do not call a difference meaningful if smaller than observed run spread.

Original M9/M10 harnesses retain their root UI. Other arms share the identical
control-free white page, 640x360 video at(40,120), exact CFR720p60 bytes, x2 canvas
and unchanged model/precision/import. Matched harness constructs actual shared
pipeline/driver with the same neural options, but minimal lifecycle callbacks.
Its contrast measures aggregate integration versus this minimal consumer, not
one specific function. There is no matched-harness baseline factorial arm: do
not claim an extension-by-workload interaction. Extension baseline/neural pairs
test whether choosing the cheaper scaler helps this same page.

Bare: no extension. Idle: installed but unactivated. No-runtime: genuine activation
with diagnostic ISOLATED requestAdapter denial; blocked candidate/discovery remains,
no GPU. This is explicitly NOT normal runtime attachment, and its failure/watchdog
path is not normal discovery cost. Record manager state separately.

## Instrumentation perturbation

Standard: common raw metadata/submission accounting plus rAF/long-task observer.
Three extra paired standard/owned neural repeats, order S/O, O/S, S/O. Three
standard/lean repeats, order S/L, L/S, S/L. Lean removes scheduling observer only;
it still includes accounting. These estimate incremental instrument cost, not
the total instrumentation effect versus unobserved playback.

Owned timing is **instrumented wrapped-callback occupancy**, includes recorder
bookkeeping and shared core, clips to the window, includes rAF/events/observers/
timers/rVFC/messages, and excludes unwrapped async continuations and browser/GPU
work. Nested categories are not additive. No total-renderer-CPU or GC attribution.
Worker start/close events and measured message calls are not full worker CPU.

## Initial long replications

Before production behavior changes: four600s windows,5s stable warmup:
legacy extension-neural1, original M10 harness1 with legacy observer/viewport,
original M10 harness2 with legacy observer/viewport, legacy extension-neural2.
All valid trials retained regardless of loss. Main purpose: test reproducibility
of unfavorable M10 result and within-protocol variation, not candidate acceptance.
First/last120s reported for each, including last-window failures.

## Data and decision boundaries

Raw local only under .cache/m105; compact summaries/hashes/recipes tracked under
owner-approved50MiB cap. Available raw is written before secondary diagnostics
validation; missing diagnostics invalidate relevant conclusions, not erase counts.
Task entries selected by start inside window retain full duration; task overlap
at boundaries remains explicit. Quality dropped counts are not decoder-only.

Report quality-drop, callback-gap, application-attempt deficit, rendered/presented
deficit and old M10 combined rate together; unique intersection unavailable.
Pipeline rate denominator is wall observation time, active duration independently
gated. No lower replacement metric or controller change without causality.
Trace only if ordinary telemetry cannot resolve the discrepancy; bounded raw
trace stays local, with exact recipe/hash and compact summary.
