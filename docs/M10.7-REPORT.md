without hiding, and a submitted frame could leave old output visible. Full

## 7. Presentation invariant

The [preregistered invariant](M10.7-PREREGISTRATION.md) permits visible replacement
only for the authoritative connected eligible owner, current intrinsic source and
exact2x backing, matching applied/current geometry and output/source epochs,
verified placement, and current clipping/control/fullscreen assumptions.

Known invalidation must hide before its handler returns. A new frame alone cannot
override dirty geometry; reconciliation alone cannot revive old-source output.
Unannounced movement has a first-following-monitored-render-update detection bound,
not atomic physical scanout. Placement tolerance is0.5 CSS pixels; stricter existing
container checks remain stricter. Final production does **not** satisfy this full
invariant, which is why the verdict is FAIL rather than a narrowed PASS.

## 8. Geometry-generation design

Attachment lifetime, source, geometry, applied geometry, output source and output
geometry have distinct generations. Refresh increments geometry and hides first.
Intrinsic/currentSrc changes increment source; submitted size/backing must match
before output can become ready. Snapshot readiness uses the same epoch predicate.

[ADR-0047](../DECISIONS.md#adr-0047---current-geometry-and-output-proofs-authorize-canvas-visibility)
records read-only proofs of the resolved style properties, clip/client metrics
and viewport actually used by inspection. Local proxies record reads during
inspection, never patch page prototypes. Guard comparisons use retained live
CSSStyleDeclarations; static readers retain a fallback for future keys. Tests
change each recorded input independently. Geometric input changes invalidate
exactly so small changes cannot compound past placement tolerance.

## 9. Fail-closed behavior

Dirty or unavailable output is hidden immediately, leaving original playback and
audio authoritative. Unsupported transforms/effects/controls, ownership loss,
security errors and observation limits preserve existing rejection behavior.
Canvas insertion is followed by a current-video and style-proof check; insertion-
induced layout change requests a fresh proof before any reveal. Destroy is terminal
and releases only owned resources and DOM.

This is bounded by **observed** invalidation. It does not make S1's unobserved
layout changes safe. Permanently hidden supported fixtures cannot pass: recovery
requires two new correct submitted frames within500ms of independently observed
settling/decoded availability, source startup within5s, and at least95% visible
samples in fixed steady windows. No limit was weakened during closure.
