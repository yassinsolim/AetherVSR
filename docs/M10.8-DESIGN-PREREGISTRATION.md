## Problem decomposition and observable limits

There is no simple generic browser "element position changed" observer.
ResizeObserver observes size, not arbitrary position-only movement. A bounded
MutationObserver sees selected DOM/attribute changes but not every resulting
layout shift or CSSOM/stylesheet edit. A retained CSSStyleDeclaration can expose
current values when read; it is not an invalidation notification. Layout polling
can detect movement but may trigger style/layout work whose cost must be measured.

Separate five obligations: source/output readiness; position/size tethering;
object-fit/crop/mask/clip; control/paint stacking; ownership and restoration.
Rect equality alone cannot prove the other obligations. Hypothesis to falsify:
cheap rect/epoch checks plus bounded events/mutations may detect all changes in
a defensible subset, while browser-native anchoring may inherit position changes
without numerical viewport reconstruction. Neither is selected in advance.

The choices are browser-maintained relationships, a cheap sentinel, an explicitly
narrow supported contract, or a named hybrid. Universal hostile-page safety is
not assumed possible. A narrowed contract must have an observable admission and
invalidation mechanism, not an assertion that the page will stay cooperative.

## Immutable media and restoration contract

Original HTMLVideoElement identity, audio, playback/seek/buffering/source authority,
controls and page references stay intact. One expensive runtime per tab, original-
video fail-closed fallback, existing exact C16D2/parity, bounded handles and complete
detach remain mandatory. No second SR implementation. Geometry-only evidence
does not establish GPU/output parity or live-processing performance.

For any anchor-name lease, record pre-lease style attribute presence and exact
text, inline anchor-name value/priority, and resolved existing names. Preserve all
existing names, add only a valid UUID-derived dashed identifier and verify it.
In an unchanged host, detach must restore the exact pre-lease inline attribute,
including absence, values and priorities. With concurrent page writes, never
overwrite those writes using a stale whole-style snapshot. Explicitly test this
conflict: a candidate cannot claim both stale-snapshot restoration and retention
of newer host state. A conflict must hide, relinquish owned state without clobber,
and be reported; an unprovable exact-restoration contract rejects that candidate.

Test multiple videos, existing inline and stylesheet anchors, escaped identifiers,
important priority, existing consumers, CSSOM changes, host style rewrites and
selectors sensitive to the style attribute. No random UUID probability claim
substitutes for observed distinct names and local collision checks. No anchor
lease may overwrite an existing page anchor configuration.

## Candidates fixed before testing

A: two-level sentinel. At presentation boundaries read current video/canvas
rectangles, intrinsic size, epochs, fullscreen and placement-parent identity.
Known events and bounded mutation dependencies invalidate synchronously. Full
style/clip/control proof runs only after invalidation or uncertainty, while hidden.
Do not include continuous full style reads and still call it the fast variant.
Test all semantic changes below; a missed one limits or rejects the architecture.

B: CSS Anchor Positioning. Geometry-only isolated prototype appends a unique
anchor-name to the video and uses fixed sibling canvas position-anchor, anchor()
edges and anchor-size() dimensions. Feature-detect each required declaration and
perform an actual resolved-layout test; CSS.supports alone is insufficient.
No polyfill or manifest-floor change. Preserve current fit/clip/control proof
obligations separately: successful tethering is not semantic correctness.
Anchor support, fullscreen, shadow scoping, collisions, priority and restoration
receive independent special review if elementary tether/restoration testing survives.

C: layout-coupled DOM. Study an owned wrapper or positioned overlay container on

permission to expand scope. A reject can be established before broad execution.

## Hard stops, selection and review

Stop a candidate immediately on a binding stale visible state, unprovable exact
restoration, mandatory MAIN monkey patch/site selector/security bypass/core change,
or mandatory invasive video reparenting/persistent host layout mutation. One
reproducible original-control/fullscreen break rejects its generic contract; do
not accumulate favorable cases to offset it. A first measured serious-candidate
window with guard p95>1ms or additional JS work>15ms/s is a clearly dominated cost
stop, retained without tuning. Lesser failures remain failed gates, not retuned
frequencies. No polishing a dominated architecture.

Classify separately: SUPPORTED+CORRECT; UNSUPPORTED+SAFE; SUPPORTED+STALE/MISALIGNED;
UNVERIFIED/NOT RUN. Safe rejection is not a product correctness failure, but an
architecture rejecting every relevant layout is not useful selection. Any narrowed
support contract requires evidence its predicate detects the excluded class.

Minimum useful selection coverage is frozen: page1px/228px/smooth, nested scroll,
preceding spacer, ancestor class/style movement, size-query movement, viewport and
video CSS resize, ABR, equivalent reparenting, container fullscreen including
nonzero-scroll exit, contain/cover, open shadow root, existing page anchors and
source+scroll overlap must remain SUPPORTED+CORRECT in all three repeats. Offscreen,
hidden/not-ready and unsafe semantic states must give safe fallback and recover
when their observable supported preconditions return. Rounded clipping and semantic
styles may be explicitly unsupported only through a prospectively stated and
demonstrated observable predicate. Rejecting one of the minimum useful layouts
can be a safety success while still making the architecture nonselectable here.
No retrospective "static pages only" exemption for invisible semantic changes.

Review problem decomposition, support-boundary logic, oracle independence, A
completeness, B semantics/style restoration, C intrusiveness, D safety, performance
protocol/statistics, stops, scorecard, ADR and next recommendation. B gets a special
review if initial tether/restoration survives. P0/P1 affecting selection requires
affected reruns. No reviewer approval substitutes for evidence or missing gates.

Final scorecard keeps correctness, cost, intrusiveness, compatibility, complexity
and failure modes separate, with supported denominators and stopped suffixes.
Choose exactly A, B, C, D, an explicitly named E, or NO ARCHITECTURE QUALIFIED.
Selection means promising enough for a separate implementation/qualification
milestone, not production readiness. Only after selection record an ADR with
measurements, support/cleanup implications and rejected alternatives. A no-selection
decision may be recorded honestly; it must not pretend anything shipped.
