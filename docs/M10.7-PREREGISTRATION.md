## Invariant and observable boundary

VISIBLE is permitted only for the current selected attachment when all hold:

1. The original video remains connected, eligible, visible and the selected owner.
2. Source generation and current intrinsic dimensions match output readiness.
3. Applied geometry generation equals current geometry generation.
4. Actual canvas placement matches the current expected video image rectangle.
5. Current placement parent, fullscreen boundary, clipping and control-stack
   assumptions remain valid under the existing conservative geometry rules.
6. Reconciliation is complete, not dirty/pending, and no known media/presentation
   transition invalidates output readiness.

Any known invalidation must hide synchronously before its handler returns.
Neither a new frame nor a new geometry proof alone may revive stale output.
Geometry, source and attachment/runtime generations are separate. Reconciliation
may restore replacement only with matching generations and a current submitted
frame for the intrinsic source. Hidden output is not a performance-tier fallback.

Tolerance: maximum absolute left/top/width/height error <=0.5 CSS pixels for
the expected image rectangle and verified actual canvas placement, including
subpixel serialization; exact2x integer backing dimensions for current source.
No228px/312px mismatch or percent-of-size tolerance. Existing stricter placement
and unsupported-geometry checks are not relaxed.

Known-dirty visible samples: zero. At every processed-frame/reveal safety boundary
and every monitored animation update after reconciliation: zero visible mismatches.
For movement without a delivered invalidation signal, a candidate watchdog has
at most the first following monitored render update to detect and hide; it must
not permit another processed/revealed frame with known mismatch. This is a
one-update detection bound for unannounced changes between checks, not a claim
of atomic physical scanout or instantaneous knowledge of arbitrary page writes.
Record pre-boundary samples too; do not erase them as eventual consistency.

Supported stable layouts must actually enhance: start the recovery clock at the
independently observed fixture layout settling, or at decoded source availability
for source transitions, not at extension readiness. Proof, two new processed frames
and visible output must occur within500ms (source reconfiguration startup bound5s).
Steady supported playback must be visible in>=95% of all sampled updates in each
fixed post-warmup60s window, including dirty/hidden/not-ready samples in its
denominator. Delayed readiness cannot postpone a window or recovery deadline.
Report hide intervals/duty fraction, recovery bounds and failures; permanently
hidden or newly rejected previously supported fixtures cannot earn a PASS without
an explicit supported-scope decision and reason. Unsupported cases must hide.
