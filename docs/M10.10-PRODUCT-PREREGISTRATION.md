## Three Independent Questions

1. Acquisition: which browser-supported path supplies video and audio, with what
   origin privileges, pixel provenance, cadence and transport?
2. Presentation: a normal extension-origin tab or popup/window owns all layout,
   canvas and controls. Optional Document PiP cannot replace that primary surface.
3. Authority: exactly PAGE_AUTHORITY for mirrors or PLAYER_AUTHORITY for replay.
   Source selection, seeks and lifecycle have one canonical generation, not two
   competing players. Presentation cannot cure unusable acquisition or authority UX.

Mirror keeps page video/source selection, buffering, timeline, seeks and ABR
canonical. Media stream transport carries frames, not extension JSON. Bounded
typed control requests may address only the selected HTMLVideoElement. Replay owns
its own timeline; source pausing/muting needs a separate explicit reversible user
action. No automatic page pause/mute as a side effect of inspection.

## Fixed Candidate Funnel

R1 direct progressive replay, optionally explicit origin-scoped privileged refetch.
R2 media-element captureStream with native clone/port probes and local WebRTC if
direct transport is unavailable. R3 chrome.tabCapture consumed in the controlled
player. R4/R5 are that exact tabCapture topology plus CropTarget/restrictTo
respectively. R6 is a browser-native self-capture CONTROL, not automatic product
qualification. No additional candidate absent material independent-review evidence.

Stages: (1) API/security feasibility, (2) deterministic media matrix, (3) input
fidelity/latency/A/V, (4) surviving-route pipeline integration, (5) credible paired
product performance. P0 local-known-input pipeline/parity is the explicit surface
control exception before acquisition. Do not run a Cartesian route/surface/media
product. Rejected topologies stop at their first binding fundamental failure;
retain complete attempted prefix and label suffix NOT RUN. Mechanism variants
prelisted here (consumerTabId or local WebRTC) are distinct, not arbitrary retries.
An apparatus defect needs evidence, a prospective correction/review and affected
reruns; raw superseded results never disappear. One invalid retry per interrupted
ordinal only; unfavorable route behavior is an outcome, not an invalid retry.

Every route/source observation is SUPPORTED, UNSUPPORTED_SAFE, UNRESOLVED or UNSAFE.
API absent/platform rejection can be UNSUPPORTED_SAFE with cleanup. Missing consent,
missing audio or unusable observation is UNRESOLVED, never a silent pass. Known
security/corruption/leaked-media/unclean teardown is UNSAFE. NOT RUN is execution
status. Advertised capability/docs/settings are not native measured behavior.

Build a separate research MV3 package, not a production-manifest variant shipped
to users. The extension-origin player is loaded as both normal tab and normal
popup-type browser window. Neither form is selected before the same native checks:
chrome-extension origin, secureContext/WebGPU, actual neural output, resizing,
owned controls, fullscreen, close cleanup, second initialization without browser
restart. No webpage DOM/CSS/MutationObserver owns its output. No acquisition yet.

Use unchanged VideoPipeline, ingest, NeuralUpscaler/C16D2, Catmull-Rom and
RuntimeDriver/RuntimeController, not a second inference engine. P0 loads the exact
known720p60 clip packaged in ignored research output. Reuse existing offline
normalized-RGBA capture helpers at1s/2s/3s: three external-import and three
forced-copy frames versus the existing standalone harness. Exact normalized input,
weights/precision and output hashes must match; capture uses isolated paused
diagnostic readbacks only, never a per-frame transport or production readback.

teardown, not aesthetics. Minimal research buttons: play/pause, seek, volume/mute,

## R1 Replay and Privileged Access

Fixed progressive matrix: packaged MP4; same-origin page MP4; cross-origin CORS;
cross-origin no-CORS; credentialed local fixture; page-created blob; page MSE.
Record PLAYABLE, ORIGIN_CLEAN_FOR_AETHERVSR and FETCHABLE_BY_EXTENSION separately.
Plain media-element playback, canvas/WebGPU import and extension fetch are different
checks. Browser security failures are expected safe outcomes, not bypass targets.

Optional refetch is normal **privileged extension-origin network access granted
by host permission**, not CORS spoofing. The user activates/selects a source and
manually grants optional origin access. Research declares only the local fixture
hosts initially; public hosts, if earned, need prospective exact-host declaration
and user approval. Chrome match patterns scope scheme/hostname, not an individual
port/path: report that grant granularity, while application validation pins the
exact origin (including port) and complete selected URL. No install-time all_urls.

The selected URL comes from an activeTab-authorized, top-frame, extension-isolated
snapshot of the explicitly selected video, bound to tab/document/owner generation.
Page/runtime messages cannot supply replacement URLs. HTTPS generally, HTTP only
for explicit loopback fixtures; reject credentials in URL, malformed URLs, unknown
schemes, unexpected source/document generation or protected media. Worker stores
the source privately; a player presents a random capability and its own registered
tab identity, never an arbitrary URL. Fetch redirect:error, bounded timeout and
byte limit, media content type checks, no generic arbitrary proxy and no segment/
manifest discovery. Revalidate URL/document before committing response. Returned
bytes stay in extension media context; never send bytes, tokens, cookies or arbitrary
fetch results to the webpage. No webRequest/DNR/header or CDM manipulation.

Credentialed fixture uses only local test cookies, no real account secrets; report
actual credentials inclusion/omission and playback difference. If auth cannot be
reproduced safely, reject that class. Blob/MSE cannot be reconstructed by guessed
manifests or site-player APIs. They are explicitly unsupported for generic replay;
do not generalize progressive replay to MSE. A progressive-only REPLAY product may
remain eligible ONLY if it meets the fixed mandatory coverage below, with MSE/auth
limitations clearly displayed. No reverse engineering is allowed to expand it.

## R2 captureStream and Transport

Capture selected page video in its legitimate document without changing host CSS.
Test progressive/same-origin/CORS/no-CORS/MSE/srcObject, seek, pause/resume, rate,
resolution changes and safely reproducible protected-state rejection. Track width,
height, settings.frameRate, observed frames, mute/ended and lifecycle are separate.
A supported getMediaStreamTrack does not establish usable transport or fidelity.

First test native structuredClone/postMessage/MessageChannel on the MediaStream,
not JSON round-trip. If rejected, one predeclared local RTCPeerConnection loopback
uses iceServers:[], complete bounded SDP/ICE control messages only and exact
generation-bound extension endpoints. It may encode/convert/resize frames: measure,
do not call it zero-copy or lossless. No TURN/STUN network server, arbitrary SDP
proxy, per-frame extension messaging, base64/image frame serialization or CPU
readback transport. Stop R2 if no practical secure transport reaches the player.

Source authority uses a typed finite command set play/pause/seek/rate, explicit
number bounds, owner/document generation and request acknowledgment. No eval,
arbitrary JavaScript/property writes or player-specific adapters. Replacing video,
navigating or closing source invalidates both directions and stops tracks/peers.
Bridge transport data is bounded; unauthorized senders/messages/old generations
are rejected. Playback exceptions are acknowledged, not assumed successful.

## R3 tabCapture, Audio and Pixel Provenance

Use the user's PHYSICAL extension action to establish activeTab invocation, then
request a source-tab stream ID with the selected tab/document identity. Prefer
worker getMediaStreamId({targetTabId,consumerTabId:playerTabId}) followed promptly
by player getUserMedia. Also test the documented visible-player create/redeem
topology if the worker/consumer combination is rejected. A no-consumerTabId probe
is a distinct documented process/origin restriction check. No frames enter the
worker. IDs are single-use/short-lived, not durable permissions. Wrong consumer,
wrong source, stale ID/generation, denial and stop must be safely rejected.

Treat tab input as COMPOSITED tab pixels until measured otherwise. Native fidelity
matrix:720p at720p-equivalent CSS, smaller and larger CSS;1080p at smaller CSS.
Record source intrinsic/CSS/DPR, track and delivered dimensions, captured full-tab
versus effective crop, already-applied browser scaling, visible overlays, normalized
RGBA differences and observed cadence. This distribution may differ from training.
No identical-input claim based only on matching dimensions or track settings.

Audio has one canonical program path. Measure source before capture, capture active,
player output enabled/muted, stop, volume and restoration. Tab capture may suppress
source local playback; explicit player AudioContext rerouting, if required, must be
measured and closed. A stream with no usable audio is not a successful player.
Do not infer audible routing, no echo or A/V sync solely from a live track. If
instrumented audio or the owner cannot establish one audible path, retain UNRESOLVED.
No microphone/system-recording consent is assumed or automated.

The target page has no privileged fetch, source selection or broker registration.

success permits scroll/resize/fullscreen/reparent/ABR and occluder tests. Element

## Fidelity, Cadence, Latency and A/V Apparatus

All measurements record machine/OS/exact browser/executable, source hash/codec/rate,
input/CSS/output extent, DPR, surface/topology, permissions/consent, import path,
window visibility and GPU timestamp availability. Use base Apple M5/24GB and actual
native Chrome with DEFAULT media policy, no focus emulation/unsafe GPU flags.
No source edits/tests/builds/competing browsers during native windows. Missing
metrics say not measured, never0. Local synthetic patterns/audio markers only;
no public screenshot/media dumps or private content in evidence.

Before mirror comparison, measure an apparatus floor using local source and local
untransported preview with synchronized flash/counter and audio markers. Freeze
a practical latency target in an addendum AFTER that floor but BEFORE mirror
latency comparison. Do not pick it from candidate outcomes. Floor does not qualify
a route. Source and consumer performance.timeOrigin clocks are bracketed; callback
time is not physical presentation/scanout. Where actual capture/receive timestamps
are available, record their semantics separately. Never infer latency from nominal
track.frameRate. If the apparatus cannot measure a bounded source-to-player delay,
mirror latency remains UNRESOLVED and no mirror may qualify.

Fidelity pre-performance: three fixed frames at matched source times for direct
replay input/output parity; for captured input, three patterned samples at native
track extent, normalized RGBA and explicit source scaling reference. Report MAE,
max error, changed pixels/extent/crop and codec/color conversion. No live pixel
readback transport: finite diagnostic captures occur in paused/offline or dedicated
measurement steps outside the pipeline hot path. If pixels are already compositor
rescaled or transport lossy, do not claim training-input equivalence; if a desired
source-only region cannot be acquired without page/chooser cooperation, generic
mirror fails mandatory input provenance rather than guessing a crop.

For surviving routes, one10s window each30/60fps measures source presented deltas,
acquired rVFC cadence, frames reaching pipeline, successful submissions/playerFPS,
duplicate/dropped counters if independent frame identity permits, mute/stall and
settings separately. Unidentifiable duplicates/drops say not measured. Dedicated
latency/A/V measurement uses local aligned flash+tone markers; report median/p95/max
and frames-delay, offset/drift, seek/pause recovery with time boundaries/sample
counts. Audio marker analysis uses actual acquired audio, not "sounds fine" or
silent video. If audio intentionally stays in source, quantify separate mismatch.

Direct replay can avoid mirror delay, but initial acquisition/load time, authority
handoff and A/V playback still require evidence. A shared video element driving
audio and GPU frames does not alone prove end-to-end sync; actual marker evidence
must PASS before either replay or mirror qualification. Missing marker evidence
is UNRESOLVED and blocks selection, not a deferrable shipping prerequisite.

The post-floor/pre-comparison addendum must pin actual audio and video endpoints,
marker schedule spanning first/last20s, estimator, absolute offset/drift limits,
and maximum permitted instrument uncertainty. Candidate outcomes cannot choose
these values. If the floor cannot support useful bounds, stop timing qualification
as UNRESOLVED without making physical-scanout claims.

## Performance and Product Gate

Only security/acquisition/fidelity/control/lifecycle survivors proceed. Instrument
acquisition/load, neural GPU and player/driver JS separately; do not invent full
capture/renderer CPU. Record input resolution before comparing GPU cost. The
controlled path does NOT reuse old arbitrary-page combined-loss thresholds as its
sole gate, and never changes historical delivery accounting.

Each serious entrant gets three fresh paired controlled-harness/route runs in fixed
H/R,R/H,H/R order,5s actual-neural post-readiness warmup +60s observation, identical
720p60 media/import/CSS output and native state. New product gate fixed prospectively:
EVERY individual observation run must have useful submittedFPS >=58 overall and
last20s, with ZERO tier fallback, probes and errors after its5s neural warmup.
No pooling/averaging can compensate for a failed run. Require
bounded observed latency (mirror target from prior floor addendum), stable A/V within
one source-frame marker resolution plus declared instrument uncertainty, and correct
cleanup. Report source/acquired rate and stalls independently; unavailable critical
operands cannot pass. GPU p50/p95 and driver/callback latency are descriptive measured
scope, not unexplained main-thread substitutes. A ten-minute soak is future shipping
qualification, not implied by three60s feasibility runs.

Latency growth across the first/last20s must not exceed one source-frame plus
apparatus uncertainty; A/V marker drift must be within that same preregistered
measurement resolution. Audible echo/duplicate paths, seconds of mirror delay,
security violation or persistent resource leak is an immediate stop. No tuning
RuntimeController, source FPS, native visibility or gate thresholds after outcomes.
