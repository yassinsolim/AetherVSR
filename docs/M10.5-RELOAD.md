## Native observations before harness correction

Runtime diagnostic reload, .cache/m105/reload-runtime-01.json: old worker target
disappeared; old isolated runtime ID became null; fixed model request failed with
Extension context invalidated; old attachment resources, manager timers and
observers reached zero; owned canvas removed, page-owned spoof retained, original

The new CDP action was sent before any fresh-worker event; it timed out after5s,
then the page/browser was closed and refresh could not recover. Browser crash
cause is not established from these records; stale extension runtime work was
not observed.

Chrome extensions-page Reload control, .cache/m105/reload-ui-01.json: **PASS,
same-document recovery**. Fresh worker observed and explicit resume acknowledged
before the new action. Old privileges failed and owned resource counts were zero;
same original video kept playing, old canvas detached, spoof preserved; explicit
new action restored exactly one runtime, baseline mode persisted, final disable
returned owned resources/timers/observers to zero and original DOM matched.

Pinned Chromium ExtensionsHandler::TriggerAction is synchronous: it invokes the
action and returns, not a promise waiting for popup/worker completion. Installed
Playwright1.63 does request worker resume but catches errors. Therefore neither
"popup promise stuck" nor "Playwright never resumes workers" is supported.

The discriminating harness repair is to await a newly registered exact-ID worker
and verified execution BEFORE sending the native action. This is a test ordering
change, not a production lifecycle workaround. Retry runtime and UI mechanisms;
seamless same-document and refresh-required outcomes must remain distinct.
