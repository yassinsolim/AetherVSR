## 4. Presentation dependency model

The two questions remained separate: observable semantics and noncorrupting
ownership. The detailed prospective matrix is in the
[preregistration](M10.9-DESIGN-PREREGISTRATION.md). Its sources are the actual
inspectGeometry decisions, attachment observers and browser behavior, not only
rectangle equality. Absent forbidden effects must still be checked for later arrival.

| Dependencies | Current production observation | CSSOM/event limitation | Simple-chain treatment |
| --- | --- | --- | --- |
| Video/canvas rectangles, parent, source/backing, viewport/fullscreen | Proof, placement/source checks, scroll/resize/load callbacks | Unannounced movement need not cause the selected invalidators | Direct live geometry/identity reads; invalidate before proof/reveal |
| object-fit/position, content box, borders/padding | Full proof and copied declarations | Fit/position can change without MO/RO/media events | Active reads; contain/cover; zero borders/padding |
| transform/translate/rotate/scale, offset-path | Existing proof covers usual transforms, not motion-path completeness | Same bounds can conceal changed image orientation | Explicit live absence predicates, including individual transforms and motion paths |
| opacity/filter/backdrop/perspective/blend, mask/clip/reflection | Full proof for existing fields | Effects can be introduced silently | Read implemented effect fields; reject nondefaults |
| overflow/client clip boxes, clip margin, radii/corner shape | Conditional full-proof style/layout reads | A clip or corner can change without box change | At most two plain clips; active zero-margin/round-corner predicates |
| display/visibility/zoom/contain/container-type/will-change/animation/transition | Partial style proof and event-triggered reconciliation | Prohibiting them once does not prove continued absence | Bounded active checks and stable reasoned rejection |
| z/order/isolation, control/caption branches, parent paint context | Style checks and sampled elementsFromPoint | Hit testing alone misses pointer-transparent captions; equal z alone ignores order | Positioned video z=0 in an isolated block parent; positive-z control branches, painted and pointer proof |

The original live geometry proof already records conditional radius reads, and
production already checks intrinsic dimensions in onFrame and listens for video
resize. This study does not claim those were absent. The new question is a smaller,
explicitly bounded continuously observed contract, not repeated full proof by default.

## 6. Support outcome taxonomy

Observed state outcomes are SUPPORTED_CORRECT, UNSUPPORTED_SAFE, UNSAFE and
UNRESOLVED. NOT RUN is an execution status, not an observed-state outcome.
SUPPORTED_CORRECT requires proved predicates; UNSUPPORTED_SAFE requires hidden/
removed output and an authoritative original. Safe rejection earns no compatibility
credit. UNSAFE includes stale visible replacement or corrupt/unreleasable ownership.
UNRESOLVED means the required observation cannot establish completion.

The final fullscreen state was safely hidden, not an unsafe exposure. The common
case is UNRESOLVED because required supported fullscreen/recovery never completed
within the fixed deadline. That blocks usefulness without claiming a safety failure.
The two ownership stops are UNSAFE even where unrelated host state was preserved
or the initiating attribute was later removed successfully.

## 9. Semantic fingerprint

[The research contract](../tools/m109-contract.ts) provides an explicit
assessContract and bounded reader. The fingerprint includes fitted-image/effect/
box/paint values, current chain and branch identities, clip geometry, source state,
fullscreen/readiness and observable output prerequisites. Prohibited fields are
actively reread; supported vendor fields are included. Parent display/ordering,
motion paths, corner-shape, clip margins, all crossed shadow roots and top-document
identity were sharpened by pre-capture review.

[The isolated monitor](../tools/m109-monitor.ts) hides and invalidates first when
input identity changes, then obtains a fresh full proof. It does not call full
inspectGeometry on an unchanged semantic input. Output geometry/backing/order are
separate live checks; a stable rejected proof does not repeatedly initialize a GPU.
It uses one unchanged real pipeline and no host-owned attributes/styles. This is
research code, not an optimized or performance-qualified implementation. Its
JavaScript allocation/serialization cost is not measured as an acceptance result.

## 11. Admission predicate

Admission returns SUPPORTED or UNSUPPORTED with a reason before reveal, based on
inspectable DOM/computed values, never a promise that the host will not mutate.
Reasons include unsupported-effect, unsupported-clipping, unsupported-control-stack,
unsupported-native-controls, unsupported-semantic-chain and lifecycle/readiness
states. The full geometry proof remains an additional necessary condition.

Pre-capture review fixed invalid numeric acceptance, axis-invalid positions,
unbounded child materialization, missed closed-root ancestry, output extent/order
and owner-scoped sequence freshness. Fake-DOM tests are labeled as such; they are
not native compatibility evidence. The native original S1 default-value rejection
shows why passing mocks is not sufficient. R1's later fullscreen rejection shows
the predicate still fails the promised minimum behavior.

## 16. Existing-anchor zero-mutation path

A preexisting page anchor was reused without changing any page-owned video,
ancestor, attribute, style or stylesheet. The unfilled owned measuring box matched
the video in four actual layouts: initial, preceding-spacer movement, 228px scroll
and CSS resize. Before/after video attributes were identical. This establishes
limited browser-coupled positioning value, not merely CSS.supports syntax.

full dynamic replacement qualification were not established. Pages need not use
anchors for an MVP, and this uncommon prerequisite is not a general solution or
a way to promote the stopped O1/O2 ownership strategies.

## 20. Minimum-usefulness result

The completed R1 prefix supports local movement/scrolling, CSS size, ABR, contain/
cover and equivalent reparenting, with observed fail-closed semantic recovery.
It does **not** complete required container fullscreen, nonzero-scroll exit or the
remaining lifecycle matrix. These requirements were fixed before results and were
not removed to make the contract pass. A 19-case prefix is insufficient usefulness.

The fullscreen video was connected, playing, readyState 4 and focused; output
remained hidden with unsupported-semantic-chain and no error. The reader uses
:modal for nonvideo top-layer rejection, but
[:modal includes fullscreen](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:modal).
This restrictive implementation predicate conflicts with the intended fullscreen
allowance. It is an engineering limitation of this stopped prototype, not proof
that the requested state cannot be observed. The allowed finite revision was
already consumed; no further candidate correction or qualification run was made.

## 25. Support-boundary interpretation

The study demonstrates why an event-only contract is insufficient for the observed
semantic properties, and why generic host mutation cannot be assumed reversible.
It also demonstrates local two-submission recovery and painted equivalence for
specific safe prefixes. These are distinct findings, not a universal solution.

The final contract stopped on an overrestrictive observable predicate, not a
proof of a fundamentally open-ended dependency surface. Late-render and remaining
adversarial completeness tests were not reached. Therefore neither "universal
replacement is possible" nor "all in-page contracts are impossible" is established.
The recommendation to pivot follows the agreed bounded-study/product gate and
the absence of a qualified useful combination, not a mathematical impossibility proof.

## 26. Selected contract/ownership outcome

Choose exactly **NO USEFUL OBSERVABLE CONTRACT QUALIFIED**.
Neither CONTRACT + OWNERSHIP QUALIFIED FOR IMPLEMENTATION nor either independently
qualified partial outcome is justified. A restoration prefix is not generic
ownership qualification, and a safe but incomplete minimum contract is not a
qualified observable support contract. ADR-0050 records this bounded decision.

There is no production rollout, new selected presentation strategy, weight/shader
change, RuntimeController retune, permission/protocol/service-worker change,
temporal SR, extension-store publication or M11 work. The original video remains
authoritative whenever the research candidate rejects.

## 27. Product-pivot gate

The gate is triggered: stop accumulating arbitrary in-page synchronization machinery
under M10.x. Recommend a separately authorized **extension-owned controlled player
or window presentation study**, where the product owns the presentation tree and
can specify stable layout/control semantics. The study must first define a lawful,
origin-clean media acquisition/cooperation path; a controlled window does not grant
DRM access or bypass CORS, autoplay or permissions.

Explicit page-cooperation APIs or declared integration adapters are alternatives
for that product decision, not hidden site-specific code in this generic contract.
No pivot architecture is selected as already implemented or qualified here.
