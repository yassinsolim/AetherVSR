## Submission boundary prerequisite

The unchanged VideoPipeline increments its monotonic submissionSequence only
after encoder.finish and GPUQueue.submit return, then invokes onFrame after its
post-submit accounting. A diagnostic-only observer cross-checks that sequence,
consumes freshness even on skipped observations, and emits only after the existing
downstream callback returns without failure. It captures frame/timing generation,
source generation, geometry generation, owner, mediaTime and backing extent.
Changing identity during that callback prevents recovery authorization. Duplicate,
skipped, stopped, destroyed and throwing callbacks cannot supply fresh recovery
credits. Registration/release must preserve newer callbacks and be idempotent.

This is the synchronous submit-returned boundary, NOT proof of asynchronous GPU
validation success, GPU completion, compositor presentation or physical scanout.
Device errors invalidate the trial and hide output; they are not favorable retries.
The observer is appended only to test builds, without MAIN-world or GPUQueue
prototype patches, core changes or production entrypoint changes. Permanent tests
exercise the actual core path, exception stages, stale identity/replay, cleanup,
reinjection, production exclusion and the exact frozen production bundle hash.
Independent review is mandatory before any two-submission recovery claim.

## Taxonomy and boundaries

Each observed state has exactly one outcome:

- SUPPORTED_CORRECT: all declared predicates hold and replacement is authorized.
- UNSUPPORTED_SAFE: output is hidden/removed and the original remains authoritative.
- UNSAFE: visible replacement violates a predicate, host state is corrupted, or
  ownership cannot be released according to its prospective contract.
- UNRESOLVED: evidence cannot establish one of the above.

NOT RUN is execution status, not a fifth observed-state outcome. Safe rejection
is safety success, not supported compatibility. Admission returns SUPPORTED or
UNSUPPORTED with a stable reason BEFORE reveal. Warmup stays hidden and records
pending readiness separately; it is not prematurely counted as support success.

The semantic obligation is checked at every actual submission callback boundary
before authorization can persist, and every candidate rAF guard. Independent
fixture samples also record action-return and render observations. Visible stale
output at an independent render observation is UNSAFE even if a later guard fixes
it. These browser-task boundaries do not measure physical exposure/scanout.

## Contracts and minimum live fingerprint

Contract **S0** is the unchanged production-presentation-S1 broad control.
Contract **S1** below is NEW and is not production S1 or M10.8 A/S2/D. The new
prospective hypothesis is a bounded simple chain with an atomic parent paint
context and active semantic fingerprint, not a geometric sentinel or periodic
full-proof timer. No prototype edits production geometry, runtime, shaders or model.

Pre-capture executable review clarification: modal/popover top-layer ancestors
are explicitly rejected using their inspectable pseudo-class state; only container
fullscreen is admitted. Every crossed shadow root must be open and the document
must be the top document. The 16-child bound includes text/comment nodes (excluding
the owned canvas), checked before materializing a list. Output rect/backing/parent
and pointer-events are separate live prerequisites, not inferred from input geometry.

S1 admits a connected, decoded, playing, non-DRM top-document video in an open
inspectable chain. Its parent is position:relative or absolute, isolation:isolate,
and display:block or flow-root (never contents, flex or grid). Video display is
block, position is relative or absolute and z-index is 0. Parent display is a live
predicate, not a one-time layout assumption; order-modified flex/grid painting is
outside this contract. It has contain/cover,
supported percentage/keyword position, zero borders/padding, no transform/effect,
transparent unadorned background, default content/object-view-box/appearance,
no CSS animation and zero transition duration. Uniform pixel video radius is
allowed only with round corner-shape; unsupported browser properties are recorded
as unavailable, not assumed to implement a shape. offset-path is none on video
and ancestors; mask-border/vendor mask-box-image/reflection must be absent where
implemented. overflow-clip-margin must be 0px on any clipping overflow axis.
At most 12 composed ancestors, two simple rectangular overflow clips,
and 16 parent children are admitted. Non-canvas sibling branches must be positioned
positive-z contexts, so their descendants paint atomically above the output.
Whitespace text is harmless; unresolved nonempty text/branches are rejected.
Rounded clipping ancestors, slots, closed shadow, unresolved zoom, native controls,
showing native tracks and unsupported paint/effects are rejected explicitly.

The per-boundary fingerprint reads only the predicates in this matrix that cannot
be inherited: video fitted-image/effect/box/paint inputs, ancestor containing-block,
visibility/effect/overflow predicates, clip client geometry, atomic-parent identity,
and direct branch positioning/z/order. Radius/box reads on ancestors are conditional
on clipping. It also checks source/backing, parent/fullscreen and readiness identity.
No stylesheet interception, MAIN bridge, complete CSS enumeration or full
inspectGeometry call is permitted on an unchanged hot-path proof. A changed
fingerprint or geometry hides first, invalidates its generation, and schedules a
fresh full admission proof. Stable rejection must not rerun full proof or initialize
a GPU every frame. Inspector output is not the independent correctness oracle.

Each fingerprint field gets an independent test: alter its value (same rectangle
where possible), observe a different fingerprint and/or explicit unsupported
predicate, and prevent stale authorization crossing another valid submission
boundary. Irrelevant inherited fields need a reason, not omission by convenience.
Adversarial tests also seek a relevant change with the SAME fingerprint, including
new clipping/effects, generated paint, background/content, branch topology and
individual transforms. Stop S1 at its first such miss. Classify it as finite missing
dependency or open-ended surface. Only a finite miss permits ONE new prospective
revision/addendum and complete affected reruns. No second revision, timer tuning,
post-hoc support withdrawal or indefinite counterexample patching is authorized.

## Ownership contracts, fixed before data

**O0 preferred:** no page-owned style/class/attribute writes and no video reparenting.
Only extension-owned canvas/DOM is created. Release removes only those nodes and
owned observers/callbacks/resources, retaining the same original video and concurrent
host changes. Snapshot parent/order/attributes, used geometry, control usability and
resource counts before/during/after. Host reactivity to insertion is a testable risk,
not assumed absent. O0 is preferred whenever its paired contract qualifies.

**Existing anchor (Q):** first characterize a preexisting, unique, usable anchor
with NO page-owned DOM, attribute, style or stylesheet mutation, including ancestors.
Only its owned unfilled measuring canvas is created and removed; it follows movement/scroll/size;
compare actual used layout, not CSS.supports alone. Test removal/replacement and
bounded lookup collision detection. This optional path cannot satisfy general MVP
usefulness alone. Only observed value in browser-coupled movement justifies O1 work.

**O1 NEW transactional property lease:** no M10.8 lease reuse. The supported grammar
is a browser-validated comma-list of literal ASCII dashed identifiers, or none;
unresolved variables/escapes/cascade materialization are rejected without mutation.
Prefer existing-anchor reuse to overriding stylesheet-only names. Acquire appends
one collision-checked UUID token to the current supported inline list, preserving
its priority. It does not snapshot or later replace the whole style attribute.
Release reads the CURRENT list and priority and removes ONLY the exact owned token.
Concurrent additions/removals/replacements/priority changes and unrelated declarations
remain. Revocation ends the lease and hides output; no token reassertion loop.

Exact restoration is prospectively semantic: current host token order, declarations
and priorities minus the owned delta, not historical whitespace serialization.
Literal occurrences of the reserved UUID remain the owned delta even when a host
rewrites a supported list; unrelated host tokens are never removed. A host may
revoke by removing the UUID, and the extension never reasserts it.

| Release situation | Exact expected property / priority / style attribute |
| --- | --- |
| Initially absent, no host anchor-property write, only UUID left | Remove anchor-name; remove empty style attribute only if this lease created it and no host style write occurred |
| Initially explicit none, no host anchor-property write | Restore none at original priority; preserve initially present style attribute |
| Current host identifiers remain after UUID removal | Preserve their current order and current priority; preserve all unrelated declarations and current style container |
| Host priority-only or same-value anchor rewrite, only UUID remains | Write explicit none with CURRENT host priority; preserve the host-written style attribute |
| Unrelated style write only | Apply the initial absent/none property rule, preserve all current unrelated declarations/priorities and host-owned style attribute |
| Host removes/readds anchor-name before observer delivery | Treat the observed replacement as host anchor ownership; remove only UUID if literal, otherwise preserve current replacement; empty resulting list becomes explicit none at current priority |
| Host removes/recreates style attribute with same text | Host owns the recreated attribute; preserve it and apply current-host-property rules |

Observe at most 64 pending attribute records, with oldValue. Drain pending records
as HOST records BEFORE each own write. Attribute only ONE exact pre-write to expected
serialized post-write transition to the extension; intermediate oldValues plus the
final current value reconstruct transitions. Extra records, including synchronous
host reactions or identical-value writes, are host records, not blindly discarded.
An identical full-style rewrite is treated as a host anchor write; a changed style
record with unchanged anchor value/priority is unrelated-style only. If an API
produces no observable record, no intent is inferred: native same-value cases must
still meet the table or the model stops. Ambiguous attribution/overflow fails closed
and is UNRESOLVED; it cannot qualify ownership. Inspect current computed ownership
as well as the inline list. A live unsupported grammar (variable/escape), including
one still resolving the UUID, is not an acquisition-only rejection: do not rewrite
that host expression or its variable. If owned-delta absence cannot be proved on
release, mark UNSAFE and stop O1. No grammar expansion after this counterexample.

Fixed O1 order: absent property; existing literal names; existing important; host
append; host replacement; host removes token; host changes priority; unrelated style;
host removes existing names; repeated acquire/release; collision; exception cleanup;
explicit none; initially absent style with host empty-style write; unsupported grammar.
Each requires no layout/control change, no token left on release, and preservation
of the declared current host state. First unsafe restoration stops O1 and its combos.
Before qualification append mandatory pending-host-write, same-value anchor write,
style removal/recreation, synchronous host reaction, history overflow, live variable
retaining UUID and live escaped-identifier cases, in that order. An ambiguity stops
qualification; unexecuted suffix remains NOT RUN.

**O2 separate:** one UUID token in data-aethervsr-anchor plus one owned stylesheet
rule supplies the browser property. Preexisting attribute collision rejects without
overwrite. Concurrent replacement/removal revokes the lease; release removes the
attribute only while the lease still owns it, and always removes its own stylesheet.
Any observed host write to that attribute, including same-value assignment or
removal/recreation, transfers the entire attribute to the host and revokes the lease.
The current host value is preserved even if it equals the former UUID; distinguish
host-adopted value from an extension-owned delta in the evidence. Use the same
64-record, exact-one-own-transition attribution rule. Unobservable/ambiguous transfer
is UNRESOLVED, never silently removed or called restored. Unrelated attributes/styles
are preserved. This IS host DOM mutation.
Fixed order: absent; collision; host replacement; host removal; same-value host write;
host remove/recreate before observer delivery; pending host write; repeated acquire/release;
exception cleanup; observer visibility; valid attribute-selector style sensitivity;
generic data-attribute observer behavior. CSS has no generic wildcard attribute-name
selector: use valid selectors and separately a generic data-* MutationObserver.
Any acquisition-induced host layout/style/behavior change stops O2. Untested suffixes
are NOT RUN, not passes; no weakening restoration after results.
